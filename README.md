# Тестовое Neowise. AI-помощник для входящих заявок

Ориентир — 45–60 минут. Менеджер вводит текст заявки, получает тему и черновик ответа. Он читает результат и сам решает, что отправить клиенту.

## Запуск

В репозитории есть сервер, HTML-страница и имитатор модели. Нужен Node.js 20 или новее. Зависимостей и ключей нет.

```sh
node server.mjs
```

Откройте http://127.0.0.1:3000. Порт можно задать через переменную `PORT`.

## Что изменить

1. Доработайте `POST /api/triage`. Принимайте JSON с полем `text`, содержащим непустую строку. При пустом, отсутствующем, нестроковом вводе или битом JSON верните HTTP 400 и `{"status":"invalid_input"}`.
2. При корректном ответе модели верните HTTP 200 и `{"status":"ready","topic":"…","draft":"…"}`. Допустимые темы — `delivery`, `pricing`, `other`. Черновик должен быть непустой строкой. При таймауте, ошибке модели или неподходящем ответе верните HTTP 200 и `{"status":"manual_review","topic":null,"draft":null}`. Ограничьте ожидание модели 300 мс. Оставьте поведение выданного имитатора прежним.
3. Покажите на странице тему и черновик при успехе. Для `manual_review` покажите понятное сообщение менеджеру и очистите предыдущий черновик. Добавьте хотя бы один исполнимый тест для поведения при сбое и инструкцию его запуска.

Для локальной проверки имитатор принимает любой обычный текст. Метки `[timeout]`, `[error]`, `[bad-json]`, `[bad-topic]`, `[empty-draft]` включают отдельные сценарии сбоя.

## Что прислать в бота

- Ссылку на pull request и SHA проверяемого коммита. Можно использовать свой учебный репозиторий. Сохраните начальный код первым коммитом, затем откройте PR из отдельной ветки.
- Короткую инструкцию запуска и прогона теста. В описании PR ответьте, где проверяется результат AI, что происходит при сбое, какой AI вы использовали и что проверили самостоятельно. Если работали без AI, укажите это.
- Одну фразу о том, какую пользу задача даёт менеджеру и как её можно измерить.

После сдачи бот может задать один-два коротких вопроса по вашему коду. Используйте учебные данные. Если не уложились по времени, отметьте незавершённые части в PR.

## Проверка решения

Запуск сервера из каталога проекта:

```sh
node server.mjs
```

Автоматические тесты API и логики страницы:

```sh
node --test triage.test.mjs
```

Тесты поднимают HTTP-сервер на свободном локальном порту. Проверяются
некорректный ввод, все пять сценариев имитатора, неподходящая структура
результата и модель, которая игнорирует отмену. Проверки клиентского кода
покрывают очистку предыдущего черновика, сетевые ошибки и таймаут,
некорректный ответ API и обратный порядок завершения запросов.

Для ручной проверки откройте http://127.0.0.1:3000, сначала отправьте
обычную заявку, затем по очереди каждую метку сбоя из инструкции выше.
Тема и черновик должны очиститься, а текст заявки остаться доступным.

## Поведение

Вход проверяется до вызова модели. Результат AI проверяется после разбора
JSON: тема входит в допустимый набор, черновик содержит текст после trim.
API возвращает только поля контракта. Ожидание ограничено 300 мс через
Promise.race; AbortController также передаёт отмену имитатору.
Любой сбой модели переводит заявку в manual_review с пустыми topic и draft.

Страница очищает прежний результат при новой отправке, выводит понятный
статус и сохраняет введённую заявку. Сетевое ожидание ограничено 5 секундами.
Номер запроса защищает экран от устаревших ответов и ошибок.
Черновик отображается как текст, поэтому HTML из модели не исполняется.

Менеджер видит, когда нужно разобрать заявку вручную, и не принимает старый
черновик за ответ на новую заявку. Пользу можно измерять временем обработки
заявки с учётом проверки и долей черновиков, принятых без исправлений.

## Использование AI и границы проверки

Решение подготовлено с помощью OpenAI Codex: реализация и тестовые сценарии.
Выполнены исполнимые проверки поведения API и клиентской логики.
Клиентские автоматические тесты используют минимальную модель DOM.
Поведение исходного mock-ai.mjs сохранено.

Ручной разбор в этом задании означает статус и сообщение на странице.
Хранилища заявок и серверной очереди в исходном приложении нет.

Страница также проверена в Chromium на успешном ответе, пустом вводе и всех
пяти метках сбоя. Подтверждены сообщение о ручном разборе и пустой черновик.
